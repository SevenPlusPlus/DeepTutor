## 本轮实现记录

已完成真实服务与页面接入，静态 Demo 继续保留用于对照。新增照片归档服务和当前资料空间内的 SQLite 表，原图使用独立永久附件，不跟随临时识题预览过期。识别由现有视觉模型抽题器完成，后台工作器由现有主节点生命周期启动和停止。

微信通道整批保存收据后再推进游标；首次接收冻结绑定账号和目标空间，重绑定不会转移旧消息。下载、原图保存和回执分开处理，数据库异常到达重试上限也会产生持久失败通知。异步保存全程持有资料空间共享活动锁，维护期间会等待后续重试，防止迁移时把数据库和附件写散。

正式页面位于 `/space/questions?view=photos`，包含科目、日期、状态与关键词筛选，原图对照、逐题编辑和选取、答案来源确认、补拍、重试、移出与恢复。已知跨科照片显示“多学科”，各题仍按各自科目筛选。复习页默认展示题目原图，图形题不会只剩文字。正式题目被删除后，照片归档会对账并恢复可审核状态，只有用户再次确认才补回题目。

主动收集使用 `partner_chat / ungraded / self_reported`，通过独立复习状态进入错题复习，不伪造自动批改结果。重复确认、多图识出同题和部分删除后的重新确认，不重置保留题目的复习计划。

## 启用步骤

1. 重启当前源码版本的 DeepTutor 服务；`deeptutor start` 会按源码变更检查并构建前端。开发时可使用已有的 `--dev` 启动方式。
2. 在伙伴的个人微信渠道中确认已登录，并通过现有绑定码流程绑定发图者账号。
3. 打开“拍照收题”。收题位置默认选择“每位发图者的默认学习空间”；需要自定义时按名称选择，目标空间仍须属于发图者。开关默认关闭，本轮没有改动真实伙伴配置。
4. 给伙伴发送题目图片。收到“已保存”回执后，可在“学习空间 → 题库 → 微信收题”查找。
5. 对照原图核对题干和每题科目，勾选确认，再加入复习；没有答案时可留空。

关闭自动收题时，单次收集支持同条图文消息或引用图片附带 `/错题`、“加入错题本”。首期没有“先单独发送指令，再等待下一张图片”的临时等待模式。
