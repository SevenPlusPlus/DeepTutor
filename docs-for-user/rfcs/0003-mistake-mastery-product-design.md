- 日期：2026-10-29

## 1. 产品判断

建议把错题本设计成一个每天可以完成的学习任务：**在伙伴微信拍下错题，网页核对后收好；每天练一小组；用跨天作答和同技能变式证明掌握；关闭后仍可追踪复发。** 收录量是资料规模，独立解决问题才是学习结果。伙伴微信负责方便地收题和告知保存结果，网页负责进度查询、原图核对、整理和正式复习，两端沿用同一份错题记录。

小学由家长帮助拍照、核对题干和安排时间，学生负责作答与说明思路；初中以学生自主管理为主，家长看到负担、进步和需要帮助的地方。首期采用同一套信息架构，通过年级调整文字长度、单次时长和家长辅助程度，不为两个年龄段重复建设系统。

家庭内也按孩子隔离资料与学习状态；家长绑定、可查看范围和管理权限需要明确授权并可撤回。原图默认随错题保留，页面提供保留与删除说明；一图多题共享原图时，移除单题不能误删其他题的来源，删除照片与学习记录分别提示影响。

默认首页是“今日复习”，一次约 10–15 分钟，可选择 5 分钟或指定科目。错题库服务查找与整理，拍照整理统一承接伙伴微信与网页选图，掌握档案展示证据与复发。家长摘要避免公开排名和连续打卡惩罚，也不把积压任务一次性压给学生。

## 2. 从收题到关闭

拍照或微信发图 → 原图可靠保存 → 分题与识别 → 核对题干 → 确认标签 → 加入复习 → 提交结果 → 调整下次复习 → 延迟验证与变式 → 已掌握 → 低频抽检，必要时重开。

每道题同时拥有两个维度的状态，避免“识别成功”被误认为“学会”：

| 维度 | 状态与含义 |
| --- | --- |
| 资料处理 | 已收图、识别中、待核对、待补拍、可复习、已移出 |
| 学习进度 | `open` 待学习/巩固中，`verify` 待验证，`closed` 已掌握；暂停与排除另设标志 |

识别失败仍保留原图；一图多题共用来源但独立复习。重复上传记录新收题事件，不重复生成错题和成功次数。主动拍照收集标记“用户认为需练习”，不伪造一次系统判错。

标签分为结构标签与个人标签：科目、年级、教材章节和知识点用于检索与教学边界；“漏条件”“概念混淆”“运算失误”用于错因；“期中重点”“老师要求”表达目标。AI 建议与学生确认分开，错因允许“暂不确定”，可批量编辑，但不以错因填写作为入库门槛。

“暂停”保留学习状态并停止主动推荐，可选择恢复日期；“排除/移出”用于非题目、重复资料或不再学习的范围。二者都不计为已掌握。学习记录和原图删除采用独立操作，避免关闭错题等同删除历史。

### 伙伴微信拍照收题

现有伙伴收题实现提供“拍照收题”开关，沿用已绑定账号的个人微信私聊，将图片归入发图者自己已授权的站内资料空间。当前绑定解析到用户与 workspace，尚未实现家庭中的多孩子映射。家庭产品后续应在伙伴设置中显式增加孩子归属，不能根据题目年级、聊天文字或当前网页所选孩子猜测；孩子归属不明确时不进入任何孩子的正式复习队列。Demo 的两个学段是严格隔离的虚拟孩子示例，没有真实身份授权系统。

开启后，该绑定私聊的新图片先按收题资料保存，再识别题目；非题目保留待移出，不自动入复习。关闭后普通图片走正常聊天，不自动归档；保留已有收题记录，单次明确收题指令沿用 RFC 0002 的约定。开关、聊天中的“已收到”、网页的“已保存”和正式“已加入复习”各自有明确含义。

当前真实微信回执只覆盖原图保存结果与网页核对入口。识别完成、核对入库、待补拍等详细进度在网页查看；对应微信通知属于后续拟议能力，不能从下面的产品流程或 Demo 对话推断已经实现。

| 阶段 | 微信与网页的分工 | 网页中同一收题记录 |
| --- | --- | --- |
| 接收与保存中 | 网页显示接收任务；不提前发送“原图已保存” | 显示接收任务，尚不宣称图片已归档 |
| 原图保存成功 | 微信回复“原图已保存，正在整理，请到网页核对” | 原图、来源伙伴、发图者资料空间和首次接收时间可查 |
| 识别完成 | 网页展示；专项微信完成通知为后续拟议 | 同一张原图关联多个草稿，可逐题改科目、知识点和错因 |
| 核对并入库 | 网页展示；专项微信入库通知为后续拟议 | 草稿关联正式错题，进入同一推荐与学习状态体系 |
| 模糊或科目不明 | 网页展示；专项微信补拍/科目通知为后续拟议 | 待补拍或待确认，不进入复习；补拍追加来源并保留首次接收时间 |
| 同字节重复原图 | 网页展示去重结果；专项微信通知为后续拟议 | 关联已有来源与题目，不重置标签、复习记录和掌握状态 |
| 原图保存失败 | “图片暂未保存成功，请重试或重发。” | 显示可重试的接收任务，不能伪装为已归档 |

同一张照片在微信来源、网页待整理和错题详情中保持关联。补拍、识别重试和跨端打开都不能新建一次复习，更不能增加掌握次数。相同消息重投幂等处理；同字节原图去重复用已有资产与来源关联。图片相似但字节不同不自动合并；相似性识别及人工合并可另行设计，不属于当前已实现去重能力。

消息送达状态与题目保存、识别和学习状态分开记录。原图已保存但微信回执发送失败时，网页记录仍可查，单独重试回执，不重新建题。伙伴不能仅凭“已归档”或学生在微信说“我会了”宣布已掌握；正式 close 继续使用本文的作答证据与策略。

首期微信保存回执提供网页核对入口，正式复习仍在网页进行。整理完成通知、确认入库通知、到期提醒、微信内提交解题过程、请求同类题和 close 通知均属于后续拟议能力；主动通知需单独选择接收人、时间和开关，提醒送达不算完成复习。以后接入微信作答时，微信消息与网页提交必须关联同一 `attempt_id`，统一判定提示暴露、独立性与掌握证据，不能两端各计一次。

## 3. 检索与每日推荐

检索先做权限与范围过滤，再在候选中排序。必须约束当前用户与资料空间；课程、科目、年级、教材、知识点、个人标签、学习状态及上传时间按用户条件取交集。默认候选为可复习的 `open/verify`，排除暂停、移出和 `closed`；家长查阅不能绕过学生数据授权。

支持“今天只有 10 分钟”“找还没掌握的分数应用题”“期中前复习几何”等请求，解析后的条件以可修改筛选条呈现。没有匹配时解释是哪项条件缩小了范围；放宽条件由用户选择，不能悄悄跨年级或混入已掌握题。用户主动指定某题或标签时允许提前练，标注“未到建议复习时间”，仍记录真实作答时间。

推荐采用两步：先估计每个学生对该题/技能的遗忘风险与复习收益，再在时间预算内组合任务。

| 因素 | 作用 |
| --- | --- |
| 个体记忆状态 | 根据距离上次有效复习的时间、历史结果、难度和间隔估计记忆下降；近期看过答案要单独处理 |
| 到期与欠账 | 到期题优先，积压分批消化；长期未练有保底召回机会 |
| 错误与掌握证据 | 连续做错、提示依赖和待完成延迟验证提高优先级；新收错题获得首次诊断机会 |
| 近期学习目标 | 用户指定知识点、考试范围提高权重，不越过年级与课程硬条件 |
| 成组约束 | 控制预计时长、难度与同知识点占比，穿插不同题型，避免一次刷多道近乎相同原题 |

MVP 可在现有 SM-2 风格间隔上增加确定性排序与组卷约束；后续有足够历史再评估 FSRS 等个体模型。排序权重、保底比例与目标记忆水平先作为可配置产品参数，通过真实延迟表现校准。固定“1、3、7、14 天”只可作冷启动策略，不宣称是所有儿童共同的遗忘规律。数据不足时明确使用默认调度，不能展示伪精确的“记忆率 82.6%”。

每道推荐给出可理解的原因，例如“上次需要提示，已间隔 4 天”“到延迟验证时间了”“你选择了期中几何”。每日任务可替换、跳过和结束；跳过不记为答错。学习一轮后展示实际完成、还需巩固、下一次建议时间，未完成部分重新排期，不滚雪球催促。

## 4. 作答与举一反三

练习默认隐藏答案和历史笔迹，支持输入答案、上传解题过程，并逐级申请提示。提交后再给正确性、关键步骤反馈和错因建议；答案不足或主观题无法可靠判定时进入“待确认”，由学生/家长核对，不能自动用于关闭。

记录原始答案、判定来源、过程得分、耗时、提示级别、是否看过解析、自信度和实际作答时间。耗时、自信度是辅助信号，不以“快”代替“会”。短时重做帮助理解，但不新增跨天掌握证据。

| 用户请求 | 题目目标 | 对母错题的作用 |
| --- | --- | --- |
| 再练原题 | 检查原解法是否能独立复现 | 更新该题记忆与作答记录 |
| 来一道同类题 | 保持目标技能，改变数值、表述或情境 | 检查迁移，提供独立变式证据 |
| 来一道进阶题 | 在已学范围增加推理或综合要求 | 扩展学习；新技能失败另建待学项 |

先从经审核题库召回，再按需生成。变式必须关联母题、目标技能、难度变化与生成版本；先校验题干完整性、答案可解性、答案与解析一致性及课程范围。低置信题留在待审核区，不直接发给学生充当测评；首期可先限制为可程序验算的题型。

同类题不能只是原题数字替换后仍暴露答案规律。进阶题如果败在母题同一目标技能，应补充母题的未掌握证据；如果败在新增技能，不因此重开已经通过验证的母题。UI 清楚说明“这道题在练什么”，避免为追求进阶不断扩大任务。

## 5. 用证据决定 close

学生看到“巩固中 → 待验证 → 已掌握”，详情展示还差哪项证据。建议首期关闭政策同时满足以下条件：

1. 原题或等价目标技能至少两次在不同日期独立通过，相邻有效复习至少间隔 24 小时，最终验证距离此前有效成功至少 7 天。
2. 另有一道相同目标技能的变式独立通过，证据不与前项重复计数。
3. 提示、解析暴露、代答、判定待确认和未解决的同技能失败均不能通过关闭门槛。

这些是待试点校准的 **MVP 产品阈值**，不是研究证明的统一掌握标准。实际间隔可由年级、题型、难度与目标调整，改规则时保留策略版本，不回写旧事件伪造证据。

一次做对进入巩固，近期已会但缺少延迟证据进入待验证；达标后系统生成掌握决策，标注时间、证据和规则版本。允许用户选择“暂不练/移出范围”，避免用一键“我会了”替代掌握证据。关闭只退出日常待练队列，档案、照片和错误历史保留。

已掌握题可在单独的低频抽检任务或用户主动复习中出现。独立作答失败且确认涉及原目标技能时重开，说明原因并重新排期；不删除此前成功证据。抽检跳过、识别错误、题目有误和新增技能失败均不直接重开。知识点整体掌握需要多题覆盖，不能从一题关闭推断整章已会。

## 6. 页面与 Demo 讲解路径

Demo 延续已有米白和陶土色界面，重点让学生回答“今天练什么、为什么练、怎样才算学会”。

| 页面 | 关键内容与可验证交互 |
| --- | --- |
| 今日复习 | 时长/科目选择、按推荐排序的题组、推荐原因、开始练习、提交结果与下次安排 |
| 错题库 | 默认未掌握，关键词/标签/科目/状态筛选，题目详情、标签编辑、主动提前练与变式入口 |
| 拍照整理 | 默认伙伴微信收题，可切换网页选图；示例对话与分阶段回执对应同一收件任务，核对、打标后加入复习；覆盖多题、科目不明、补拍、重复与接收失败 |
| 掌握档案 | 跨天记录、独立/辅助作答区别、待验证条件、关闭依据与重开 |
| 设计说明 | 展示状态规则、推荐逻辑和示例数据边界，供产品评审查看 |

建议演示：先在拍照整理查看伙伴微信的已绑定身份与孩子归属，模拟发一张图片，比较“收到”“原图已保存”“待核对”的阶段；在旁边网页核对同一收件任务的题干，确认入库，再到错题详情加“期中重点”。回今日复习查看来源与推荐原因，练一次原题并对比“独立做对”和“用了提示”；请求同类题，最后查看掌握档案的时间证据与关闭条件。可另选多题、科目不明、模糊补拍、重复或接收失败场景，检查它们不会越过入库和复习门槛。不能通过演示连续点击三次就模拟真实跨天达标，历史案例需明确为预设记录。

原型使用浏览器本地示例数据；微信对话、收题开关、绑定状态与回执全部模拟，不扫码、不发送真实消息，也不改变伙伴真实设置。网页选图只做本机预览，识别、判题与生成结果均为预设演示，不连接生产微信、OCR、模型或学习账户。它用于评审流程，不代表识别准确率、通道可靠性、调度有效性或学习效果。

## 7. 数据与服务边界

| 实体 | 主要责任 |
| --- | --- |
| 收题来源与收据 | 复用 RFC 0002 的通道事件、照片收据、原图与题目关联；冻结来源身份、已授权资料空间与首次接收时间，独立记录回执状态；家庭版另补孩子映射 |
| `Question` | 不可变题目版本、题干、答案、解析与来源附件 |
| `PersonalMistake` | 学生与题目的关系、来源、处理/学习状态、暂停与排除原因 |
| `Tag` | 科目/知识点/个人标签，建议来源与确认状态 |
| `Attempt` | 真实提交、判定、提示暴露、原题/变式及目标技能证据 |
| `ReviewState` | 记忆调度参数、due_at、失败与有效间隔统计、策略版本 |
| `VariantRelation` | 母题、变式、目标技能、扩展技能、难度与审核结果 |
| `ReviewSession` | 用户条件、时间预算、推荐清单、推荐解释与完成情况 |
| `MasteryDecision` | 关闭/重开事件、证据 attempt 引用、原因与规则版本 |

领域服务提供收题确认、检索、推荐、提交、变式请求与掌握决策；模型负责建议与生成，不能直接改学习状态。提交用 `attempt_id/idempotency_key` 去重，写入 attempt、更新调度与状态决策保持一致；并发提交做版本校验。所有读取、附件和变式关系均校验 owner/workspace，客户端状态不可作为关闭凭据。

当前可复用伙伴微信通道、照片收题服务、拍照导入、标签、作答事件、SM-2 风格调度和 AI 出题。微信收题复用既有发图者身份与其授权资料空间校验；家庭中的孩子映射与相应授权属于后续产品建设，网页收件任务与正式错题的关联继续保留。收题无需先跑一次聊天模型才能保存。现有队列尚不能以 `resolved` 表达严格关闭，也未完整排除已关闭题；应新增学习状态与证据决策，统一所有队列入口的过滤。AI 出题需补母题关系与验题流程，避免单独生成一张练习卷后丢失闭环。专项整理/入库/close 微信通知、到期提醒和微信作答仍是后续设计，不由现有收题代码或静态 Demo 推断已经实现。

## 8. 分期与验收

MVP 先将伙伴微信可靠收题与网页审核打标接通，再打通未掌握检索、短任务推荐、作答记录和证据关闭；同类题优先用审核题库，有限题型生成；提供家长摘要与重开。下一阶段再评估微信到期提醒和跨端作答，并做个体调度拟合、更丰富手写批改、综合进阶和知识点覆盖，均以真实样本验证为前提。

主要效果指标是“至少间隔 7 天后的独立同技能变式通过率”。同时看已关闭题复发率、成熟错题队列的关闭率、每日任务完成与退出、实际用时、识别修正率及判题争议率。关闭率只统计已有足够观察窗口的队列，避免拿刚入库题或简单题刷高结果；不以题量和打卡天数替代学习收益。

| 验收场景 | 必须结果 |
| --- | --- |
| 模糊图、无答案、多题、重复收图 | 原图可追溯；未确认题不进练习；不伪造判错与复习次数 |
| 伙伴微信身份未绑定、孩子归属不明 | 给出绑定或归属确认入口，不进入任何孩子的正式错题与复习队列 |
| 收题开关关闭、原图保存失败、回执失败 | 关闭后普通图片不自动归档；原图失败不声称已保存；回执失败不回滚已有题目或触发重复建题 |
| 微信与网页查看同一任务、补拍或合并 | 题目来源与首次接收时间可追溯，不清空已有复习记录；跨端操作不增加掌握次数 |
| 检索未掌握、课程/年级/标签交集 | 不回 closed 或越权数据；空结果允许明确放宽条件 |
| 指定提前练或同日连续重做 | 允许练习，但不补造间隔证据，不提前 close |
| 看解析后答对、AI 判定不确定 | 记录辅助/待确认，不计独立掌握证据 |
| 完成跨天原题与变式验证 | 生成可追溯关闭决策，退出日常推荐，保留历史 |
| closed 抽检失败、进阶新技能失败 | 前者确认后重开；后者只记录对应新技能问题 |
| 请求重投、并发提交、暂停/移出 | 不重复更新间隔；不跨状态覆盖；移出不计掌握 |

本次交付为方案与静态页面。生产上线前需分别完成识题、判题、变式正确性和延迟学习效果试点，验收阈值由真实学生样本与人工复核共同确定。

## 9. 学习依据与适用边界

以下研究支持间隔、主动提取、近迁移与混排的设计方向。把这些原则组合成儿童错题本，以及“两次跨天、7 天延迟、另一道变式”的关闭政策，属于本方案的产品选择，不能从研究直接推导其次数和阈值。

| 来源 | 对本方案的启发与边界 |
| --- | --- |
| [Cepeda 等，2008：Spacing Effects in Learning](https://doi.org/10.1111/j.1467-9280.2008.02209.x)，[作者稿](https://laplab.ucsd.edu/articles/Cepeda%20et%20al%202008_psychsci.pdf) | 最优学习间隔随目标保持时长而变化；支持调整间隔，不能推出固定复习日历。研究为事实记忆任务，不能直接代替儿童数学验证 |
| [Roediger 与 Karpicke，2006：Test-enhanced Learning](https://pubmed.ncbi.nlm.nih.gov/16507066/) | 提取测试相较重复阅读有更好的延迟保持；支持先作答后反馈。材料为文章记忆，不证明做对一次便掌握解题技能 |
| [McDaniel 等，2013：Quizzing in Middle-School Science](https://pdf.retrievalpractice.org/transfer/McDaniel_etal_2013.pdf) | 初中科学课堂中的应用练习可促进同内容的部分近迁移；支持用新情境检验，不承诺任意跨学科或远迁移 |
| [Rohrer 等，2020：Interleaved Mathematics Practice](https://uweb.cas.usf.edu/~drohrer/pdfs/Rohrer_et_al_2020JEdPsych.pdf) | 七年级数学课堂试验支持混排已学题型；用于任务多样性设计，不据此宣称混排比例适合所有年级和所有新知识 |
| [Anki 官方 FSRS 文档](https://docs.ankiweb.net/deck-options.html#fsrs) | 调度参数可按复习历史拟合，目标保持率与复习负担需要权衡；这是记忆调度工具说明，不是解题能力或 close 标准 |
